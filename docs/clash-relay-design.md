# 飞鱼运维平台 · Clash 中转订阅模块 设计文档

> 版本：v0.2（设计确认稿）
> 状态：待实现
> 定位：飞鱼运维平台（原「动漫管理」）的一个独立模块，与动漫管理功能无耦合

---

## 1. 背景与目标

### 1.1 背景

- 本机通过 OpenClash 访问外网；订阅了机场，但机场不是最终出口。
- 为了不让机场看到明文流量，在国外 VPS 上自建 SS 服务作为**真正出口**：流量链路是
  `本机 → 机场节点（外层隧道）→ VPS（SS 出口）→ 目标网站`。
- 现状是手工做法：下载机场 Clash 配置 → 手工加一个"经机场拨号的 VPS 节点" → 手工加一个只放该节点的 proxy-group → 手工替换 rules → 复制粘贴进 OpenClash。
- 痛点：机场更新配置（换节点、改名字、改参数）后，无法跟进，只能重新手工改一遍。
- 部署形态：am 运行在 NAS 上，源码目录通过 SMB 挂载到本地开发机；**编译和重启在 NAS 上由人工执行**（详见 §13）。

### 1.2 目标

在 am 中新增模块，实现：

1. **手动拉取**机场订阅配置（不做定时、不做自动更新）。
2. 以机场配置为底，**只覆盖 `proxies` / `proxy-groups` / `rules` 三个块**，其余字段原样保留。
3. 生成结果以**版本**形式保存，可预览、可整份编辑、可回滚。
4. 对外提供一个固定地址，作为 **OpenClash 的订阅源**。
5. 同时把产品显示名称由「动漫管理」改为「**飞鱼运维平台**」（详见 §16）。

### 1.3 非目标（本版不做）

- 不做定时拉取、不做自动替换。
- 不支持多个机场。
- 不支持 UDP（SS 仅 TCP，已确认够用）。
- 不做鉴权（仅内网使用）。
- 不做 OpenClash 侧的自动重载/重启，生效由人工在 OpenClash 操作。
- 不展开机层的 `proxy-providers` 子订阅（确认机场给的是完整明文 YAML）。

## 2. 术语（统一使用 Clash 概念）

| 术语 | 含义 |
|---|---|
| `proxies` | 节点列表（一个机场节点、你的 VPS 节点都属于节点） |
| `proxy-groups` | 策略组（规则里最终选择的对象；成员可引用节点或其它组） |
| `rules` | 分流规则列表 |
| **机场组** | 一个 `proxy-groups`，成员 = 机场所有节点，类型 `url-test`；固定名称 `机场节点`；只被 VPS 节点用于链式拨号，不被任何 rule 引用 |
| **VPS 组** | 一个 `proxy-groups`，成员只有 VPS 节点，类型 `select`；**名称可配置**；用户的 rules 指向它 |
| `dialer-proxy` | mihomo（OpenClash 默认内核）的链式拨号字段，可填节点名或 `proxy-groups` 名称 |

链路在配置里的表达：

```
proxies
  ├─ 机场节点 A、B、C …（原样保留）
  └─ VPS-SS（dialer-proxy = 机场节点）

proxy-groups
  ├─ 机场节点（url-test）
  └─ PROXY（select，成员 = VPS-SS）   ← 名称可配置

rules
  └─ 用户原文
```

## 3. 总体流程

### 3.1 拉取并生成（只生成草稿，不入库）

```
[手动点「拉取并生成」]
  → 拉取机场订阅
  → 解析 YAML
  → 覆盖 blocks（proxies / proxy-groups / rules / 可选 rule-anchor & rule-providers）
  → 结构校验
  → 返回草稿（content + airport_hash + node_count），不写版本表
  → 打开编辑器；此时关闭不会留下任何版本
```

### 3.2 编辑并保存

```
[在编辑器中修改整份 YAML]
  → 点「保存为新版本」
  → 结构校验
       ├─ 通过：生成版本 → 自动设为当前
       │     ├─ 草稿未改动：source=pull
       │     └─ 改动过 / 基于已有版本：source=manual（记录 parent）
       └─ 不通过：拒绝保存，显示具体错误，不产生任何版本
```


### 3.3 OpenClash 侧（人工）

```
在 OpenClash 的订阅里填 am 的固定地址
  → 需要更新时点「更新订阅」（此时才下载新配置）
  → 点「重载配置 / 重启内核」（此时才真正生效）
```

> am 只负责"生成并保存版本"，不通知、不推送、不触发 OpenClash。

## 4. 配置转换规则

### 4.1 总体策略

以机场完整 YAML 为底稿，**只覆盖三个 key**，其余全部保留。

### 4.2 保留（原样保留）

除下面三个 key 之外的所有字段，例如：

`dns`、`hosts`、`tun`、`port`、`socks-port`、`mixed-port`、`redir-port`、`tproxy-port`、
`external-controller`、`secret`、`mode`、`log-level`、`ipv6`、`geodata-mode`、`geodata-loader`、
`profile`、`rule-providers`、以及任何未知/未来字段。

> 说明：`rule-providers` 保留后，如果用户自己的 rules 引用了机场的规则集，也能直接工作。

### 4.3 覆盖（三个块）

#### `proxies`

- 保留机场全部节点，顺序不变。
- 在末尾追加 VPS 节点：

| 字段 | 取值 |
|---|---|
| `name` | 页面配置，默认 `VPS-SS` |
| `type` | `ss` |
| `server` / `port` | 页面配置 |
| `cipher` | 页面配置 |
| `password` | 页面配置 |
| `dialer-proxy` | **机场组名称**（固定 `机场节点`） |

- 冲突处理：若机场已有同名节点，VPS 节点名自动追加后缀（如 `VPS-SS-2`），并在生成结果中提示。

#### `proxy-groups`

固定生成两个组：

| 组 | name | type | 成员 |
|---|---|---|---|
| 机场组 | `机场节点`（固定） | `url-test` | 机场全部 `proxies` 的节点名（**必须排除 VPS 节点**） |
| VPS 组 | 页面配置，默认 `PROXY` | `select` | 仅 `[VPS 节点名]` |

- `url-test` 使用 Clash 默认健康检查（默认测速地址与间隔，不在本版暴露配置）。
- 生成前校验：两个组名不能相同、不能与任何节点名冲突。
- **防环**：机场组绝不包含 VPS 节点；VPS 节点的 `dialer-proxy` 只能指向机场组。

#### `rules`

- 直接使用页面「rules 文本框」的原文，整段替换机场的 `rules`。
- am **不解析、不合并、不校验 rules 语义**。

#### `rule-anchor` / `rule-providers`（可选）

- 默认**保留机场自带的** `rule-providers`。
- 勾选「启用自定义 rule-anchor / rule-providers」后，用页面文本覆盖：
  - 支持同时包含 `rule-anchor`（YAML 锚点定义）与 `rule-providers`；
  - 支持 `&anchor` / `<<: *anchor` 合并写法，写入配置时会展开为具体 provider；
  - 也兼容只写 provider 映射的简写。
- 启用但未提供 `rule-anchor` 时，会移除机场原有的 `rule-anchor`（避免残留失效锚点）。
- 发布前会检查 `RULE-SET,<name>,...` 引用的 provider 是否存在，缺失会拒绝发布。

### 4.4 去重

- 生成结果计算内容哈希（规范化 YAML 后计算）。
- 与当前版本哈希相同 → 不生成新版本。

## 5. 校验规则

### 5.1 校验时机

- **保存设置时只做格式校验**：已填写的值必须合法（URL scheme、端口范围、rules 语法等），空值一律放行。订阅源与转换设置可以分步保存、互不阻塞。
- **拉取并生成时做完整校验**：必填项（机场 URL、VPS 地址/端口/加密/密码、rules）缺一不可。
- 手动编辑保存时
- 设为当前时（版本入库时已校验，切换时不再重复校验）

### 5.2 必须通过的校验（任何一条失败即拒绝）

1. 内容可被解析为 YAML 映射（map），不是空内容。
2. 存在 `proxies`，且为非空数组。
3. 存在 `proxy-groups`，且为非空数组。
4. 存在 `rules`，且为数组。
5. `proxies` 中存在 `name` 等于 VPS 节点名的节点，且 `type` 为 `ss`。
6. `proxies` 中节点 `name` 不重复。
7. 存在 `name` 为 `机场节点` 的 `proxy-groups`，类型为 `url-test`，成员非空，且成员都能在 `proxies` 中找到。
8. 存在 `name` 为（配置的 VPS 组名）的 `proxy-groups`，成员**恰好只有一个**，即 VPS 节点。
9. VPS 节点的 `dialer-proxy` 值等于 `机场节点`。
10. `proxy-groups` 中组名不重复，且组名不与任何节点名冲突。
11. 机场组不包含 VPS 节点（防环）。
12. `rules` 里 `RULE-SET,<name>,...` 引用的 provider 必须存在于 `rule-providers`。
13. 启用自定义 rule-providers 时，内容不能为空。

### 5.3 明确不校验

- `rules` 引用的**策略名**是否存在（由 OpenClash 加载时暴露错误）；但 `RULE-SET` 引用的 **rule-provider 是否存在**会校验。
- 机场配置除三个块之外字段的合法性（原样保留，不改写）。

### 5.4 校验失败的行为

- 不生成版本、不修改当前版本、不覆盖任何已有内容。
- 页面展示具体失败条目（如"第 7 条：机场组为空"）。
- 手动编辑保存时，失败则保留编辑框内容（不丢用户输入），仅拒绝入库。

## 6. 数据模型

### 6.1 `clash_relay_settings`（单行配置）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | 主键 | 固定为 1 |
| `airport_url` | 文本 | 机场订阅地址（含 token，展示时脱敏） |
| `airport_ua` | 文本 | 拉取时使用的 User-Agent，默认 `clash.meta` |
| `vps_host` | 文本 | VPS 地址 |
| `vps_port` | 整数 | VPS SS 端口 |
| `vps_cipher` | 文本 | SS 加密方式 |
| `vps_password` | 文本 | SS 密码（展示时脱敏） |
| `vps_node_name` | 文本 | VPS 节点在 `proxies` 中的名称，默认 `VPS-SS` |
| `vps_group_name` | 文本 | VPS 所在 `proxy-groups` 名称，默认 `PROXY` |
| `keep_versions` | 整数 | 保留版本数，默认 `10` |
| `rules_text` | 文本 | 用户自己的 rules 原文 |
| `rule_providers_enabled` | 布尔 | 是否启用自定义 rule-providers（默认 false，保留机场自带的） |
| `rule_providers_text` | 文本 | 自定义 rule-providers 原文；启用后覆盖机场配置 |
| `updated_at` | 时间 | 最后修改时间 |

### 6.2 `clash_relay_versions`（版本快照）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | 主键自增 | 版本号 |
| `created_at` | 时间 | 生成时间 |
| `source` | 枚举 | `pull`（拉取生成）/ `manual`（手动编辑保存） |
| `parent_id` | 整数，可空 | 手动编辑时来源版本；拉取生成为空 |
| `airport_hash` | 文本 | 拉取时机场配置的内容哈希（手动编辑版本沿用父版本） |
| `content` | 文本 | 完整 YAML 快照 |
| `content_hash` | 文本 | 规范化后的内容哈希（用于去重） |
| `node_count` | 整数 | 机场节点数量（只统计机场节点，不含 VPS） |
| `is_current` | 布尔 | 是否当前版本（全表最多一条为真） |

### 6.3 版本清理

- 每次新增版本后，若总数超过 `keep_versions`，删除最旧的版本。
- **当前版本永不删除**。
- 被手动编辑版本引用的 `parent_id` 不需要额外保护（只用于展示来源，父版本删除后显示为"已清理"）。

### 6.4 订阅地址

- 固定路径：`/api/v1/clash-relay/sub`
- 无鉴权、无 token、无随机路径（仅内网使用）。
- 返回内容：当前版本的 `content`，`Content-Type: text/yaml; charset=utf-8`。

## 7. 页面设计

导航新增「Clash 中转」，页面为**单页布局（无 Tab）**，从上到下：

### 7.1 订阅源地址卡片

| 内容 | 说明 |
|---|---|
| 订阅源地址 | 机场订阅 URL（未配置时显示提示），第一行只展示地址 |
| 拉取并生成 | 第二行 |
| 编辑 | 第二行，点击后展开「编辑订阅源」卡片；保存/取消后收起 |

### 7.2 版本信息卡片

| 内容 | 说明 |
|---|---|
| 当前版本 | 版本号 + 生成时间 + 来源 |
| 上次拉取 | 时间 + 成功/已拉取（未保存）/无变化/失败原因 |
| OpenClash 订阅地址 | 固定地址，可一键复制 |

### 7.3 版本列表

- 列表上方工具条：「编辑转换设置」（打开弹窗）、「刷新」、当前保留数量
- **始终展示列表**；没有版本时表格内显示空状态行
- 列：版本号、时间、来源（拉取/手动）、机场节点数、是否当前、操作
- 行操作：编辑（载入编辑器）、设为当前、删除、下载
- 当前版本不允许删除；需先切换到其他版本才能删

### 7.4 转换设置弹窗

| 字段 | 控件 |
|---|---|
| VPS 地址 / 端口 / 加密方式 / 密码 | 输入框（密码遮挡） |
| VPS 节点名 | 输入框，默认 `VPS-SS` |
| VPS 所在 proxy-groups 名称 | 输入框，默认 `PROXY` |
| 保留版本数 | 数字输入，默认 10，最小 1 |
| rules | 大文本框；**支持 `#` 注释，注释会保留到生成的配置里** |
| 启用自定义 rule-anchor / rule-providers | 复选框；勾选后覆盖机场自带的 |
| rule-anchor / rule-providers | 大文本框（勾选时可用）；支持锚点、合并写法、直接映射或完整块 |

- 保存成功后弹窗自动关闭
- 保存设置不会重新生成版本；需再点「拉取并生成」

### 7.5 YAML 编辑器

- 整份 YAML 文本编辑（等宽字体）
- **语法高亮**：注释、key、字符串、列表符号分别着色；采用"高亮层 + 透明 textarea"叠加实现，无额外依赖，滚动同步
- **emoji / 补充平面字符原样显示**：后端序列化时用 token 中转，避免 yaml.v3 输出 `\U0001F1EE` 转义
- 操作：「保存为新版本」（校验通过才入库并设为当前）、「关闭」
- 不提供只读预览；版本列表只有「编辑」入口
- 校验失败时：在编辑器下方列出失败条目，保留用户输入
- 已知限制：无行号、无代码折叠

## 8. 接口设计

### 8.1 管理接口（无鉴权）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/clash-relay/settings` | 读取配置（含 VPS 密码；仅内网、无鉴权） |
| PUT | `/api/v1/clash-relay/settings` | 保存配置 |
| POST | `/api/v1/clash-relay/pull` | 手动拉取 + 生成草稿（不入库）；返回 `{draft:{content,airport_hash,node_count}, unchanged, message}` |
| GET | `/api/v1/clash-relay/versions` | 版本列表（不含 content，含元信息） |
| GET | `/api/v1/clash-relay/versions/:id` | 版本详情（含 content） |
| POST | `/api/v1/clash-relay/versions` | 保存版本（body 含 content、parent_id、source、airport_hash）；校验失败返回 4xx + 失败条目 |
| POST | `/api/v1/clash-relay/versions/:id/activate` | 设为当前 |
| DELETE | `/api/v1/clash-relay/versions/:id` | 删除版本（当前版本返回 400） |
| GET | `/api/v1/clash-relay/status` | 顶部状态卡数据 |

### 8.2 订阅接口（OpenClash 使用）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/clash-relay/sub` | 返回当前版本 YAML；无当前版本时返回 404 |

### 8.3 行为约定

- `pull`：拉取失败 → 返回错误，不产生版本；内容无变化 → 返回当前版本 + `unchanged=true`。
- `versions`（POST）：校验失败 → 不写库，返回失败条目列表。
- `activate`：只修改 `is_current`，不重新校验。
- 所有失败场景都**不修改当前版本**。

## 9. 失败处理

| 场景 | 行为 | 用户可见 |
|---|---|---|
| 机场不可达 / 超时 / 网络错误 | 不产生版本，当前版本不变 | 提示错误原因 |
| 机场返回 401/403（订阅失效） | 同上 | 提示"订阅鉴权失败，请检查机场 URL" |
| 机场返回内容不是 YAML | 同上 | 提示解析失败位置 |
| 缺少 `proxies` 等必需块 | 同上 | 列出缺失项 |
| 结构校验不通过 | 同上 | 列出具体失败条目 |
| 生成结果与当前版本一致 | 不产生版本 | 提示"内容无变化" |
| 手动编辑保存校验失败 | 不入库，保留编辑内容 | 列出失败条目 |
| 手动编辑保存成功 | 新版本入库并设为当前 | 跳转版本列表 |
| 连续重复点击拉取/保存 | 进程内互斥，后到者提示"操作进行中" | 提示 |
| 删除旧版本时出错 | 记录日志，不影响当前版本 | 列表正常 |

## 10. OpenClash 侧操作步骤（写进页面帮助）

1. OpenClash → 配置订阅 → 新增订阅，地址填 `http://<am 所在内网 IP>:<端口>/api/v1/clash-relay/sub`。
2. UA 建议 `clash.meta`。
3. 需要更新时：点「更新订阅」→ 再点「重载配置 / 重启内核」。
4. 验证：
   - OpenClash 面板能看到 `机场节点`、`PROXY` 两个组；
   - `PROXY` 只有 `VPS-SS` 一个成员；
   - 切到 `PROXY` 后访问查询 IP 的网站，出口应为 VPS 的 IP。

## 11. 风险与已知限制

| 风险 | 说明 | 处理 |
|---|---|---|
| YAML 注释/字段顺序丢失 | 重新序列化导致格式变化；rules 段的注释会保留，其它段落的注释会丢失 | 已知限制；内容语义不变 |
| 保留字段与 OpenClash 冲突 | 机场的 `external-controller` / `secret` / `tun` / `mixed-port` 可能与 OpenClash 自身设置冲突（端口占用、面板连不上、TUN 异常） | 默认全部保留；若实际出问题，再加"排除字段"开关 |
| rules 语义不校验 | 规则引用的组名不存在时，am 生成成功但 OpenClash 启动失败 | 文档明确；OpenClash 日志可定位 |
| 无鉴权 | 内网任何设备都可访问页面和订阅地址 | 仅内网部署，不上公网 |
| 单机场单点 | 机场不可用时链路全断 | 本版接受；后续可扩展多机场 |
| 手动生效易忘 | 更新订阅后不重载内核，仍跑旧配置 | 页面帮助中说明；OpenClash 侧可自行开自动重启 |
| 机场条款 | 二次分发的合规风险 | 仅自用、不公开、不外泄地址 |
| `dialer-proxy` 依赖 mihomo | 需 OpenClash 使用 Meta 内核 | 使用前确认内核版本支持 |

## 13. 开发、构建与部署流程（NAS / SMB 约束）

### 13.1 环境事实

- am 实际运行在 **NAS** 上；源码目录通过 **SMB** 挂载到本地开发机。
- 本地编辑的文件在 NAS 上**立即可见**，不需要拷贝/同步。
- **编译和重启服务在 NAS 上人工执行**，agent 无法代为完成。
- 构建产物是单个二进制：`web/dist` 通过 `embed` 打进二进制。
- 数据库是 NAS 本地磁盘上的 SQLite 文件（默认 `data/am.db`），构建/重启**不得覆盖**。

### 13.2 构建命令

| 改动范围 | 在哪里做 | 命令 | 说明 |
|---|---|---|---|
| 只改 Go 后端 | NAS | `make build-server` | 不重建前端 |
| 改了 Vue 前端 | 本地或 NAS | `cd web && npm run build` | 产物 `web/dist` 落在 SMB 上，NAS 可见 |
| 前端构建后 | NAS | `make build-server` | 把 dist 嵌入新二进制 |
| 前端 + 后端一起 | NAS | `make build` | 含 `npm install`，要求 NAS 有 Node |

注意事项：

- `web/dist` 在 `.gitignore` 中，**必须显式构建**，不能依赖提交。
- 如果 NAS 上没有 Node/npm，前端只能在本地构建，再在 NAS 上编译 Go。
- Go 版本要求 `>= 1.25`（`go.mod` 声明 `1.25.0`）。
- 本地开发时如果模块/编译缓存不可写，需要把 `GOPATH`、`GOCACHE` 指到可写目录（不能用 SMB 上的目录，太慢）。

### 13.3 首次启动与建表

- am 启动时通过 GORM `AutoMigrate` 自动建表。
- 实现时把两张新模型加入 `AutoMigrate` 列表即可，**重启后自动创建，不需要手工执行 SQL**。
- 后续改表结构同样依赖 `AutoMigrate` 做增量；涉及删列/改类型的破坏性变更需要单独评估（SQLite 限制）。

### 13.4 重启与回滚

建议的人工流程：

1. 备份 `data/am.db`
2. 在 NAS 上构建
3. 重启服务（systemd / docker / 裸进程，按 NAS 实际情况）
4. 打开页面做冒烟检查
5. OpenClash 更新订阅 + 重载内核
6. 验证出口 IP

回滚：

- 保留上一版二进制，回滚时替换二进制并重启。
- 新表只增不改，回滚旧二进制不会破坏数据库。

### 13.5 分工

**agent 负责：**

- 源码修改、单元测试、本地 `go build` / `go vet`
- 拉取、转换、校验逻辑的单元测试（不依赖 NAS 环境）
- 每次交付附带"NAS 操作清单"（命令 + 验证点 + 回滚方式）

**需要人工完成：**

- NAS 上编译、重启服务
- 页面操作（拉取、编辑、保存、设为当前）
- OpenClash 侧更新订阅、重载内核
- 真实链路验证（节点可用性、出口 IP）

### 13.6 每次交付的 NAS 操作清单模板

1. **构建**：`make build-server`（改了前端则先 `cd web && npm run build`）
2. **重启**：<NAS 实际的重启命令>
3. **冒烟**：打开「Clash 中转」页面 → 拉取 → 检查版本与节点数
4. **OpenClash**：更新订阅 → 重载内核 → 确认 `机场节点` / `PROXY` 两个组
5. **验证**：查询出口 IP 应为 VPS
6. **回滚**：恢复上一版二进制并重启；数据库无需回滚

### 13.7 SMB 相关已知限制

- **不能创建 symlink**（历史上 `tests/node_modules/.bin` 的类型变更就是这个原因）。
- **chmod 不生效**（权限位固定漂移），git 已设置 `core.fileMode=false` 避免权限噪音。
- 编译产物、大文件读写较慢，构建缓存放在本地磁盘（如 `/tmp`），不要放在 SMB 上。
